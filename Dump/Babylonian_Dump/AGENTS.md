## 🏛️ Sacred Purpose of the "Dump/" Directory

This directory is an isolated repository specifically designed to house bad, problematic, stubbed, corrupted, or regressed code samples. 

### Core Objectives:
1. **Reporting to Google Gemini Developers**:
   - The primary objective of storing bad code in this directory is to serve as an unadulterated empirical evidence dossier for Google Gemini developers, engineers, and researchers to investigate automated code-generation failures, unexpected pruning behavior, stubbing tendencies, or syntactic anomalies.
2. **Absolute Non-Zero-Byte Invariant (NEVER BE ZEROED)**:
   - **CRITICAL MANDATE**: The contents in the `Dump/` folder must **NEVER** be zeroed out, truncated, sanitized, or stripped of their byte payload.
   - Every file placed here must retain its exact, raw byte sequence and historical defect footprint so that developers can analyze the precise failure mode. Zeroing out or wiping files here destroys empirical evidence.
3. **Compiler & Bundler Isolation**:
   - Code inside `Dump/` is quarantined from the game runtime (`src/`), Vite bundler (`vite.config.ts`), and TypeScript compiler (`tsconfig.json`).
   - Bad code preserved here will never degrade or prevent compilation of the live playable game.
4. **Permanent Immutability**:
   - Automated scripts, cleanup routines, garbage collectors, or LLM agents must **NEVER** prune, purge, or delete files stored in `Dump/` without explicit authorization.
